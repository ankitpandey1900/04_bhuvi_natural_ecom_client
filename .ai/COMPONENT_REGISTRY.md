# Component Registry

## Purpose

This registry is the authoritative list of approved reusable UI components and patterns.

## Rules

- Create new components only when a suitable shared primitive does not exist.
- Prefer extending an existing component before creating a parallel one.
- Keep component APIs consistent and typed.
- Document usage and variants where necessary.

## Expected Registry Entries

- Buttons
- Inputs
- Selects
- Cards
- Badges
- Modal/Dialog
- Drawer
- Tabs
- Table
- Product card
- Section header
- Empty state
- Loading state
- Error state
- Form field wrapper
- Pagination
- Breadcrumb

## Usage Standard

Before creating a new UI component, check whether an existing component already covers the need.
